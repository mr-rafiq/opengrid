# Feature parity ledger

Reference: AG Grid **36.2.0**, public React documentation reviewed on **2026-10-29**. OpenGrid is an independent MIT implementation with its own API. Both Community and Enterprise capabilities are in scope. Full parity is **not met**; this is not a drop-in compatibility or affiliation claim.

## Status and evidence

- **Implemented** means the stated bounded OpenGrid slice exists and has named automated verification. It does not promise every reference API option.
- **Partial** means a working subset exists; the limitations are part of the support contract.
- **Missing** means no supported implementation exists. A type, example or extension seam alone is insufficient.

This ledger currently has **58 broad categories: 4 Implemented, 49 Partial and 5 Missing**. Related requirements are combined and categories vary greatly in size; these counts are not a completion percentage or an enumeration of every reference API option.

Tests live alongside their modules: [core](../packages/core/src/core.test.ts), [extensions](../packages/core/src/extensions.test.ts), [ranges](../packages/core/src/ranges.test.ts), [server-side](../packages/core/src/server-side.test.ts), [viewport](../packages/core/src/viewport.test.ts), [formula engine](../packages/core/src/formula-engine.test.ts), [React grid](../packages/react/src/grid.test.tsx), [React ranges](../packages/react/src/ranges.test.tsx), [column virtualization](../packages/react/src/column-virtualization.test.tsx), [editors](../packages/react/src/editors.test.tsx), [charts](../packages/react/src/charts.test.tsx), and [exports](../packages/export/src/export.test.ts). The [verification record](VERIFICATION.md) owns executed command results; links here describe test scope, not a replacement run report. No manual screen-reader verification has been performed.

## Four distinct row models

The [reference row-model documentation](https://www.ag-grid.com/react-data-grid/row-models/) separates four loading strategies. DOM virtualization is rendering, not a remote provider. `DataGrid` consumes a client `GridModel`; separate read-only `ServerDataGrid` and `LiveViewportDataGrid` bind their respective provider stores. The flat infinite loader remains standalone.

| Model                                                                     | Status  | Boundary and evidence                                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client-side                                                               | Partial | Resident rows processed locally; core immutability/order tests. Pivot helper is independent from grid mode.                                                                                                                                                                       |
| [Infinite](https://www.ag-grid.com/react-data-grid/infinite-scrolling/)   | Partial | Flat blocks, bounded LRU, deduplication, query cancellation/invalidation and manual retry. Exact count required; no unknown-count mode or React scroll binding. Extension tests verify store behavior.                                                                            |
| [Server-side](https://www.ag-grid.com/react-data-grid/server-side-model/) | Partial | Provider-authoritative group/pivot block store plus read-only ServerDataGrid: paging, route drilldown/breadcrumbs, server sort/filter, loading/retry and loaded-page selection. No mixed-route expansion, server-wide selection/write editing or automatic pivot schema.          | Server-store and remote React tests; backend persists writes. See [bindings](REMOTE_GRIDS.md).       |
| [Viewport](https://www.ag-grid.com/react-data-grid/viewport/)             | Partial | Buffered push store plus read-only LiveViewportDataGrid: sparse absolute-index rows/placeholders, scrolling subscriptions, logical navigation and scaled physical scroll space. External query configuration; no editor/selection/interactive column layout or bundled transport. | Viewport-store and remote React tests cover stale pushes, count changes, bounded DOM and live focus. |

See [remote models](REMOTE_MODELS.md) and [React bindings](REMOTE_GRIDS.md) for validation, cancellation, ownership and persistence boundaries. In-memory provider/component tests are not a hosted production-backend claim.

## Next delivery priorities

1. Extend remote bindings to mixed-route expansion, automatic pivot result columns, server-wide selection and write workflows.
2. Add formula-aware editing/highlighting/reference rewrites, native calculated-column menus and structural migration.
3. Extend ranges/clipboard/modal editing and existing AST builder; add independent multi-filter panels and full menus/panels.
4. Add group-resize/married-child semantics, spans/nonresident pinned totals, automatic detail measurement, pivot totals/UI and richer charts/import/export.
5. Establish scale benchmarks and manual screen-reader/touch/cross-browser evidence.

These are engineering priorities, not a completion-date promise. Public source, passing tests and broader modules do not establish full AG Grid parity.
