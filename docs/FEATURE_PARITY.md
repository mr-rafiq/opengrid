# Feature parity ledger

Reference: AG Grid **36.2.0**, public React documentation reviewed on **2026-10-29**. OpenGrid is an independent MIT implementation, with its own API. This ledger is a requirements map, not a claim of drop-in compatibility, affiliation, or full parity. Both Community and Enterprise capabilities are in scope; features will not be placed behind a commercial gate in OpenGrid.

## Reading the ledger

- **Implemented** means the stated OpenGrid slice exists and has named automated verification. It does not mean every option in the reference API is supported.
- **Partial** means a working subset exists; the limitation column is part of the support contract.
- **Missing** means no supported implementation exists. Examples, interfaces, and extension points do not count as implementation.

Evidence paths: [`core.test.ts`](../packages/core/src/core.test.ts) exercises the model; [`extensions.test.ts`](../packages/core/src/extensions.test.ts) exercises analytics, arithmetic formulas and block loading. React/browser verification is recorded separately by the integration owner. Rows involving UI remain partial where supported behavior is narrower than the reference. No percentages are used: counting a single checkbox for a complex subsystem would hide material gaps. Full AG Grid parity is not met.

## Four distinct row models

The [official row-model documentation](https://www.ag-grid.com/react-data-grid/row-models/) distinguishes client-side, infinite, server-side and viewport strategies. DOM virtualization is a rendering optimization and does not implement a remote row model.

| Model                                                                     | OpenGrid status | Boundary and acceptance criteria                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------- | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client-side                                                               | Partial         | All supplied rows resident in memory; filtering/sorting/grouping locally. Core tests cover edit immutability and processing order. Pivot helper is separate from the grid model.                                                                                |
| [Infinite](https://www.ag-grid.com/react-data-grid/infinite-scrolling/)   | Partial         | Standalone flat block loader provides bounded LRU cache, concurrent deduplication, cancellation/invalidation and manual retry. Extension tests verify those cases. No React scroll integration or unknown row count; response requires exact nonnegative count. |
| [Server-side](https://www.ag-grid.com/react-data-grid/server-side-model/) | Missing         | Needs hierarchical requests for group/pivot/aggregate operations, cache eviction, refresh/retry, transactions and selection semantics. Fetching one page is insufficient.                                                                                       |
| [Viewport](https://www.ag-grid.com/react-data-grid/viewport/)             | Missing         | Needs visible-range subscription, server-pushed data, generation ordering, unsubscribe cleanup and stale-update tests.                                                                                                                                          |

## Delivery sequence

1. Complete cross-feature core/React verification, packaging and browser interaction checks. Maintain exact test results alongside each release.
2. Add range selection/clipboard, column virtualization, schema-safe state restoration, full editor lifecycle and consistent accessible menus.
3. Add pivoting and richer tree/group behavior with reproducible large-data benchmarks.
4. Implement infinite and server-side row models as distinct tested strategies; then viewport subscriptions.
5. Add formula/calculation engines and optional chart/export packages. Every optional dependency requires a license and supply-chain review.
6. Close remaining UI/platform gaps and run manual screen-reader, touch and cross-browser checks before claiming mature parity.

These are engineering priorities, not a completion-date promise. A public repository or passing foundation tests do not mean the complete roadmap is implemented.
