## Current and next checkpoint acceptance

The vertical-span checkpoint renders one owner cell across adjacent eligible rows, omits covered cells, and retains an offscreen owner when its tail intersects the viewport. It preserves pin regions and original logical ARIA positions, supports owner editing/undo and keyboard/Find navigation, bounds memory/comparison work, and clips at pages, groups, details, full-width rows and pin/depth boundaries. The combined checkpoint now requires matching horizontal owner footprints before vertical joins and retains origins across both windows. Merged range/export operations remain explicitly unsupported. Its guide and verification record own the precise limits and executed results.

The resident set-list checkpoint adds source-wide typed value indexing and staged searchable/paged checkbox dialogs. It retains exact integer/date/negative-zero identity, preserves drafts across incoming data, fences external filter conflicts and uses native modal keyboard/touch controls. This closes the previously missing resident scalar-list workflow; it does not complete tree/remote lists, availability cascades, Excel modes, complete multi-filter display modes/lifecycle or menus.

The fixed-sheet formula checkpoint connects explicit raw expression atoms to computed model values and a native Formula/Literal cell editor. It adds mixed atomic history, complete candidate result validation, fixed source references and bounded silent reads. Rich expression completion/range authoring, reference-aware clipboard/fill, structural rewrites and full-row formula sessions remain substantive gaps; the standalone engine and this adapter do not establish Excel compatibility.

The searchable choice checkpoint closes the single-string rich picker workflow: bounded immutable named choices, locale-folded contains/prefix/fuzzy search, fixed-height virtualized options, staged Apply/Cancel, disabled choices, async abort/retry and cell/row-form validation/history integration. It does not complete multi-select, complex objects, custom option rendering, remote search, staged multi-cell review or the reference editor lifecycle. The editing family remains Partial.

The next React priorities are custom React menu components and panel lifecycle, multi-filter display variants, formula-authoring workflows, merged bulk/export behavior, structured translation codes for remaining diagnostics and remote write handling. Remaining touch drag/device work stays tracked alongside these. Pointer handlers without touch tests or backend request types without an editable conflict/retry flow will remain partial. Combined owners now validate matching footprints; rectangle-aware range and export operations still need their own data semantics and validation.

Complete unit, production build, real-browser and site checks must pass with one local worker, followed by exact-commit CI/Pages and live-flow verification. The [verification record](VERIFICATION.md) records executed results. No manual screen-reader, touch-device or performance certification is inferred from automated checks.

Named multi-filters now support one to four independent child controls, immutable intersecting query models, local child staging, parent Apply/Cancel, external-source conflict decisions and nested-modal focus recovery. This closes the basic independent composition workflow, while reference display modes, cross-child faceted availability, nested composition and remote/tree value services remain open. See [independent filters](MULTI_FILTERS.md).

The contextual-command checkpoint adds real data-cell clipboard, edit, note, selection, history and CSV commands, owned bounded custom items, native modeless keyboard menus and cooperative async cancellation. It preserves equivalent range/language changes while rejecting delayed paste through changed view order. This closes the basic context-command workflow, while hierarchical/custom/group/remote menus and aggregate status extensions remain open.

The column-header checkpoint adds working sort, physical pinning, resident grouping/expansion, current/rendered sizing, proportional fit, per-column width reset, filter/chooser focus and guarded visibility commands. It reuses the tested popup surface with a true header context, owned custom items and sizing cancellation. Full reference menus remain Partial: custom React components, aggregation, absolute sorts, renaming, calculated authoring, empty-header invocation, full layout reset and panel lifecycle/virtualization still need implementation. See [column commands](COLUMN_MENUS.md).

The nested-command checkpoint adds owned globally bounded submenu trees shared by cell/header menus, current-level keyboard/RTL, real mouse/touch activation, native stack geometry, shared cancellation/retry and narrow popup focus reveal. Four levels and 48 total items do not complete custom React menu-item rendering, group/remote targets, export/chart integration or panel lifecycle. See [nested commands](NESTED_MENUS.md); both broad menu families remain Partial.

### Reference constraints and OpenGrid extensions

The current 36.2.0 [column-spanning constraints](https://www.ag-grid.com/react-data-grid/column-spanning/#column-spanning-constraints) state that cell selection does not work correctly with column spans and that one column cannot use both colSpan and spanRows. OpenGrid's bounded combined rectangles are its own extension. Unavailable merged selection combinations should not be presented as promised reference behavior. Bounded content-driven height now closes a substantive reference capability: the [row-spanning guide](https://www.ag-grid.com/react-data-grid/row-spanning/#auto-height-and-row-spanning) supports measuring wrapped content and assigning excess height to the final row of a span.

The automatic-height checkpoint measures mounted ordinary and merged owners, assigns span excess to its final row, retains bounded estimates, reflows fixed/flex widths and anchors visible source positions. Remaining automatic full-width/header/group and remote sizing keep the three broad families Partial. See [height contract](AUTO_ROW_HEIGHT.md).

The automatic-detail checkpoint extends the shared bounded observer to natural client detail regions, with separate cell/detail identities, independent merged allocation, async grow/shrink, source-position anchoring, pins/full-width masters and nested-grid demo controls. Nested persistence, remote lifecycle and document fidelity remain open. See [detail sizing](AUTO_DETAIL_HEIGHT.md).

The server-request checkpoint adds real FIFO concurrency/backpressure, retained actual canceled-provider slots across queries, atomic refresh admission and synchronous-abort ownership, bounded failure messages, and a retained-cache React retry that invokes the provider again. The local manual provider demo exposes actual active/canceled calls and queued demand. This closes bounded request scheduling; the later grouping checkpoint adds bounded mixed-route rendering and visible-route reservations. Backend writes/selection and automatic pivot columns remain open within the Partial family. See [server requests](SERVER_REQUESTS.md).

The runtime-definition checkpoint adds atomic client replacement in the mounted React grid, stable-ID layout/query retention, stale draft/range/filter cancellation, cache/merged-height invalidation and an accessible zero-column view. Fixed-schema alignment links detach and can be recreated. This closes ordinary client replacement, while formula/calculated structural dependency rewrites, remote/pivot result schemas, reference identity matching and complete lifecycle events remain open. See [runtime definitions](COLUMN_DEFINITIONS.md).

The resident grouping checkpoint adds a compact optional row-group panel, owned desktop drags and equivalent native keyboard/touch controls, stable aggregate group sorting, top/bottom filtered subtotal/grand rows, localized labels and print projection. It preserves source selection, range exclusions, span boundaries and ordinary flattened pagination. A bounded simultaneous mixed-route read-only view is now implemented; richer total/pivot workflows remain open. See [row grouping](GROUPING.md).

The remote grouping checkpoint adds route-qualified simultaneous sibling/nested expansion, explicit branch paging, provider-authoritative query/aggregate rendering, bounded active cache reservations, same-query generation resets and retained-branch retry. Collapse and unmount release reservations; over-capacity expansion is rejected atomically. The breadcrumb view remains available. Automatic subtree infinite scrolling, remote writes/selection/notes in the new tree binding, pivot schema and server total responses remain open. See [remote grouping](GROUPING.md#simultaneous-remote-branches).

The client pivot checkpoint adds a bounded flat multi-key matrix, controlled Rows/Columns/Values panel, owned native dragging and keyboard/touch alternatives, weighted raw-source totals, retained stable-ID result layout and formula-neutralized CSV. Hierarchical pivot row expansion/subtotals, remote result schema UI, custom operations, post-aggregate filters and pivot charts remain partial. See [client pivot tables](CLIENT_PIVOT.md).

The provider-sidebar checkpoint connects controlled visibility, owned native dragging/grouping, built-in value choices and staged typed conditions to the actual server block/tree query model. Compatible definitions retain local layout; both bindings format provider aggregate slots without synthetic source rows. Infinite/viewport panels, distinct-value/pivot/schema/write/selection and richer total/detail workflows remain open. See [provider sidebar](SERVER_SIDEBAR.md).

The delayed-clipboard checkpoint fences pending React toolbar operations by owner/schema/state/range/view and latest intent; editor opening cancels pending reads without losing drafts. This closes the reproduced lifecycle races while multi-range, rich HTML, formula-reference rewriting and broader performance/manual accessibility evidence remain open. See [clipboard behavior](API.md#cell-ranges-clipboard-and-fill).

The keyboard/scale verification checkpoint adds forced-color/reduced-motion focus round trips, native menu/input focus retention, explicit functional DOM budgets and exclusive local test-server ownership. It does not establish general performance or manual assistive-technology certification. See [keyboard and scale checks](KEYBOARD_HARDENING.md).

## Host-owned request boundary

Version 0.10.0 adds native [host-owned edit requests](EXTERNAL_EDITS.md), including getter/fieldless draft submission, preserved class references and explicit requested UI states. The application still owns persistence, ordering/conflicts, asynchronous validation and acknowledgement, retries and backend undo. Source-specific AG event/component/state contracts and authenticated integration remain unverified; a native submission API alone does not close those gaps.

## Typed editor and view seams (0.11.0)

Native custom editors now accept typed drafts without class coercion, and a [client view controller](GRID_VIEW.md) exposes real focus/reveal/scroll/edit commands with virtualized ownership and lifetime checks. The original demo uses a domain-instance review choice. Native rich list options remain string-keyed. Generated-group business edits, a complete AG component/API/state adapter and authenticated application acceptance remain open; these additions do not promote those families to complete.

## Domain grouping and hierarchy seams (0.12.0)

Native string grouping keys preserve original class-valued reads; generated-group callbacks and explicit blank comparators use real hierarchy metadata. Frozen source/filtered/sorted forests remain independent of the rendered page. The original class-grouping demo exercises filtering, totals and virtualized horizontal keyboard focus in both color modes. See [domain grouping callbacks](GROUP_CALLBACKS.md).

Internal row/column/value adapters have separate original regressions and private read-only source-conformance checks. They are not a public AG Grid facade or a complete application replacement. Unbalanced reference grouping, complete component/filter/panel/API/state translation, asynchronous business edits/paste, backend permissions and authenticated visual acceptance remain open. The existing broad-category partial status is unchanged.
