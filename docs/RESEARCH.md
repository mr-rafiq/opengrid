## OpenGrid implementation evidence

Current source includes ranges/TSV/fill; both-axis windowing with explicit variable row/detail heights; grouped headers; typed/async/custom and modal row editors; a validated advanced-filter AST/builder; literal Find and plain-text notes/UI; getter caching; hierarchical server-side/live viewport stores and read-only React bindings; a dependency formula engine; SVG charts; and real XLSX/PDF output plus bounded XLSX import. These are original implementation observations, distinct from reference-document observations. The [API](API.md) links contracts, [parity](FEATURE_PARITY.md) records subsets and [verification](VERIFICATION.md) owns executed commands.

Remote store/binding tests use provider fixtures and in-memory simulations, not a hosted production backend or full server expansion/write semantics. Formula tests establish language/dependencies, not Excel compatibility or formula-aware cell editing. Export tests inspect independent-reader bytes; import tests exercise a separately bounded parser/preview, not general workbook fidelity. PDF Unicode limits remain. Chart tests cover supported projections, not full chart parity. Callback-count cache/geometry tests are not latency benchmarks; keyboard/ARIA checks are not manual screen-reader verification.

## Remaining evidence limits

Additional source supplies all five percentage display transforms with explicit parent-denominator tables and exact BigInt ratios, bounded static browser-print snapshots, shared-column-state alignment, integrated pinned/full-width rows, compiled calculated columns and controlled custom filters. Their guides retain explicit limits: no automatic parent discovery, physical-printer certification, horizontal-scroll alignment, complete formula-aware authoring or reference multi-filter display/lifecycle compatibility is inferred. Managed row moves add resident-order history and a bounded React interaction; they do not establish external transfers or transformed-view reparenting.

No AG Grid runtime scenarios were recorded in this pass. Documentation establishes described capabilities, not internal algorithms, performance, edge-case behavior or accessibility outcomes. OpenGrid tests establish only their executed cases. A browser engine passing a keyboard test does not establish screen-reader usability.

The public [row-spanning specification](https://www.ag-grid.com/react-data-grid/row-spanning/) was revisited for the vertical-span milestone. It describes merging contiguous equal-value leaf cells, custom adjacent predicates and automatic-height integration. OpenGrid's compact run index, clipping rules, budgets and interaction semantics are independently designed; automatic-height integration and combined two-dimensional spans remain separate gaps.

The row/column spanning guides were revisited for the later combined-span checkpoint. OpenGrid now defines a bounded matching-footprint rule before vertical joins, preserving one rectangle owner through both virtual windows, pinning, navigation and edits. This is OpenGrid's own combined contract; the reference guides do not establish identical combined behavior. Automatic height, merged clipboard/range operations, merged exports and remote layout remain separate gaps.

The public [set-filter overview](https://www.ag-grid.com/react-data-grid/filter-set/) and [data-update guide](https://www.ag-grid.com/react-data-grid/filter-set-data-updates/) were revisited for the resident scalar-list milestone. Search, matching-value selection and staged actions are reference requirements. OpenGrid independently uses canonical typed indexes, paged native checkboxes, whole-source counts and explicit conflict/reload handling. Its current scalar comparison includes typed invalid values in the blank/null bucket, and its normal edit pipeline immediately re-filters; these boundaries are documented rather than presented as identical reference behavior. Tree/remote distinct values, cross-filter availability and Excel modes remain open.

The [formula overview](https://www.ag-grid.com/react-data-grid/formulas/) was revisited for editable fixed sheets. The reference describes per-cell expression entry, dependent updates and richer editor/fill interactions. OpenGrid's separate adapter deliberately uses explicit raw atoms, constructor-bound source IDs, a native Formula/Literal mode editor, computed scalar/null projections and atomic final-sheet validation. This is working grid integration rather than the earlier standalone lab. Completion/range authoring, structural and relative-reference rewrites, custom functions and workbook expression fidelity remain separate requirements.

The public [rich select overview](https://www.ag-grid.com/react-data-grid/provided-cell-editors-rich-select/) and [customisation guide](https://www.ag-grid.com/react-data-grid/provided-cell-editors-rich-select-customisation/) were revisited for the searchable choice milestone. The reference inventory includes searching, virtualized choices, formatting, asynchronous values, multi-select and complex objects. OpenGrid independently implements a bounded single-string native modal, immutable named-choice index, locale-folded search, explicit Apply/Cancel and its existing validation/history/session integration. Multi-select, complex values, custom option rendering and remote query text remain open; matching the reference editor lifecycle is not claimed.

The [feature ledger](FEATURE_PARITY.md) records implementation status separately from these observations. Each future release should preserve its source version, actual test commands/results and unverified boundaries. Re-review the reference before expanding a parity claim; the live documentation may change.

The public [hierarchy selection guide](https://www.ag-grid.com/react-data-grid/grouping-row-selection/) was revisited for resident subtree actions. Its inventory distinguishes individual, descendant and filtered-descendant selection. OpenGrid independently defines source subtrees, including eligible data-bearing parents, compact interval/prefix resolution, page-target unions and fresh-state fences. Generated group IDs remain outside source selection. Remote/global rules, custom eligibility and complete reference configuration remain gaps.

The public [multi-filter guide](https://www.ag-grid.com/react-data-grid/filter-multi/) was revisited for named child composition. OpenGrid independently defines a bounded frozen slot schema, active-child intersection, nested staged controls and explicit source-conflict decisions. Reference display variants, cross-child availability and complete custom lifecycles remain gaps; no enterprise implementation was copied.

The public [context-menu guide](https://www.ag-grid.com/react-data-grid/context-menu/) was revisited for contextual command requirements. OpenGrid independently supplies flat typed action metadata, native modeless popovers, actual existing workflow callbacks, explicit ownership/cancellation and committed clipboard-view fences. Reference submenus, custom item components, aggregate/remote targets and complete export/chart menu integrations remain open. Native Popover API behavior was checked against [MDN documentation](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API/Using); executed Chromium evidence does not certify every browser or assistive technology.

The public [column-menu guide](https://www.ag-grid.com/react-data-grid/column-menu/) was revisited against version 36.2.0 for header invocation, sorting, pinning, sizing, grouping, filtering and chooser requirements. OpenGrid independently connects those bounded resident operations through its existing model and shared menu surface, with a true column context and operation-specific sizing signals. Reference nested/custom item rendering, aggregation, absolute sorts, rename/calculated authoring, empty-header invocation, full layout reset and complete panel lifecycle remain gaps. Logical inline scroll comparisons preserve an equivalent nonzero offset during an RTL switch; actual changed scrolling still dismisses commands.

The [menu-item component inventory](https://www.ag-grid.com/react-data-grid/component-menu-item/) was revisited for nested command requirements, and the [W3C menu pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/) supplied primary keyboard/ARIA guidance. OpenGrid independently implements bounded owned submenu descriptors, native child popovers and shared task ownership; no reference implementation code was used. Four-level mouse behavior, native light dismissal, current-level keys, RTL, narrow popup scrolling and stationary-pointer focus ownership have dedicated tests. Custom React menu components and complete reference lifecycle remain separate gaps; automated checks do not certify full assistive-technology conformance.
