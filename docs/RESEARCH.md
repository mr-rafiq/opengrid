## OpenGrid implementation evidence

Current source includes ranges/TSV/fill; both-axis windowing with explicit variable row/detail heights; grouped headers; typed/async/custom and modal row editors; a validated advanced-filter AST/builder; literal Find and plain-text notes/UI; getter caching; hierarchical server-side/live viewport stores and read-only React bindings; a dependency formula engine; SVG charts; and real XLSX/PDF output plus bounded XLSX import. These are original implementation observations, distinct from reference-document observations. The [API](API.md) links contracts, [parity](FEATURE_PARITY.md) records subsets and [verification](VERIFICATION.md) owns executed commands.

Remote store/binding tests use provider fixtures and in-memory simulations, not a hosted production backend or full server expansion/write semantics. Formula tests establish language/dependencies, not Excel compatibility or formula-aware cell editing. Export tests inspect independent-reader bytes; import tests exercise a separately bounded parser/preview, not general workbook fidelity. PDF Unicode limits remain. Chart tests cover supported projections, not full chart parity. Callback-count cache/geometry tests are not latency benchmarks; keyboard/ARIA checks are not manual screen-reader verification.

## Remaining evidence limits

Additional source now supplies all five percentage display transforms with explicit parent-denominator tables and exact BigInt ratios, bounded static browser-print snapshots, and shared-column-state alignment. These are partial feature-family implementations: no automatic hierarchy/display-state integration, physical-printer certification or horizontal-scroll alignment is inferred. Row-projection groundwork does not establish pinned/full-width client-grid support.

No AG Grid runtime scenarios were recorded in this pass. Documentation establishes described capabilities, not internal algorithms, performance, edge-case behavior or accessibility outcomes. OpenGrid tests establish only their executed cases. A browser engine passing a keyboard test does not establish screen-reader usability.

The [feature ledger](FEATURE_PARITY.md) records implementation status separately from these observations. Each future release should preserve its source version, actual test commands/results and unverified boundaries. Re-review the reference before expanding a parity claim; the live documentation may change.
